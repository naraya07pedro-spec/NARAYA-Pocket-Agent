## 2026-11-10 | P1-P atomic first-monitor identity admission and no orphan pilot slots (PR #22 MERGED, source/local only)

**Concrete source finding:** P1-O registered a new authenticated identity with a D1 INSERT **before** inserting its first PAUSED monitor in a separate DB operation. If the second operation errored or silently inserted zero rows, a newly registered identity could remain stranded without any monitor, permanently occupying one of the **20** pilot identity slots. This is a documented source-level failure scenario, **not evidence of a real remote Cloudflare incident**.

**Implemented:**
- New-user **valid explicit first POST** executes a **single Cloudflare D1 `batch()` transaction**: (A) atomically insert capped/unique `issuer+subject` identity, (B) insert PAUSED monitor referencing the winning identity in SQL with existing per-owner monitor cap and unique draft/repo protection, and (C) conditionally remove **only the request's own identity candidate if it has no monitors**. If B throws, D1 rolls back A. If B is ignored and C removes the candidate, API returns generic 500 rather than claiming 201. On ambiguous D1 `meta.changes` missing/out-of-range, fail closed.
- Existing registered owners continue indexed lookup and regular monitor insert, without redundant identity writes. Unknown user **GET list still returns empty without registration**, and valid unknown-account observation/PAUSE remains 404. JWT verification, route/body prevalidation, 20-user cap, 3-monitor cap, same-draft idempotency and isolation remain.
- Added three Node tests: inject error **after identity INSERT** in a transactional batch and inject zero-change monitor insert, asserting **zero persisted identities and monitors**, failure response, same-draft retry 201, subsequent retry 200; also simulate a **committed** first-monitor batch with missing D1 change metadata and verify HTTP 500 plus safe retry 200 without duplicates. Strengthened a **real local Cloudflare workerd/D1** integration test with a **valid SQL unique-key failure** that can only occur after the first statement registered the candidate, proving D1 rolls it all back, then succeeds on retry. Added preflight mutation guard for atomic batch + request-specific candidate cleanup.
- New [ADR-0017](ADR/0017-atomic-first-monitor-onboarding.md) records semantics, threat model, provider D1 transaction documentation, and limitations. No new D1 schema migration, external account, cloud deployment, credential, scheduled job or API write.
